# 应用守护

在 WebUI 的“管理 › 应用守护”中，系统管理员或拥有“应用守护策略”系统权限的账号可以为全校教室电脑统一开启应用守护，让 ClassIsland 保持运行：

- **退出自启**：ClassIsland 被正常退出后自动重新启动。可设置延时，例如“退出 40 分钟后自启”；设为 0 时立即启动（实际至少等 10 秒，让 ClassIsland 自己的重启先完成）。
- **开机自动启动**：登录 Windows 后 1 分钟内 ClassIsland 没有自己启动时，由守护程序启动它。只决定守护是否代为启动，不会改动 ClassIsland 自身的“开机自启”设置；守护程序本身始终随登录运行。默认开启。
- **意外退出时重启**：ClassIsland 崩溃或在任务管理器中被结束后，5 秒内重新启动。10 分钟内意外退出超过 3 次时，暂停自动重启 10 分钟并上报“频繁崩溃”事件。
- **增强守护**：首次启用时在教室电脑上请求 UAC 管理员授权，安装固定名称的 Windows 自动启动服务 `RemoteCI.Guard` 和登录任务 `RemoteCI\Guard Agent`。服务只维护普通权限用户代理，不以管理员身份启动 ClassIsland；拒绝授权时保留普通守护。
- **独立云端通道**：守护使用同一设备凭据独立连接服务器。ClassIsland 与插件退出后设备仍显示“守护在线 · 课表离线”，系统管理员可从控制页远程打开 ClassIsland，也可以关闭或卸载守护。
- **多路径备份**：除默认备份外，最多设置 3 个额外绝对路径；每个目标使用独立的 `RemoteCI.Guard.Backup` 子目录和清单，恢复时逐个尝试。还可在 `%LOCALAPPDATA%\RemoteCI\ProtectedBackups` 下启用 ACL 受限的安全备份目录，子目录名可自定义，留空则随机生成并复用。
- **自定义守护进程名**：可设置字母、数字、点、下划线和连字符组成的代理文件名。改名时插件会迁移登录自启项和增强任务；代理始终从 `%LOCALAPPDATA%\RemoteCI\Guard` 运行，增强服务从 `%ProgramData%\RemoteCI\Guard` 运行，均不占用或锁定 ClassIsland 安装目录。
- **禁止删除**：定时把 ClassIsland 备份到默认位置和额外目标。检测到程序被删除后，从备份恢复、重新启动，然后用 ClassIsland 原生对话框提示：

  > 当前ClassIsland由{组织名}统一管理，请勿自行删除，当前实例已由RemoteCI自动恢复。

  组织名在“系统设置 › 常规 › 组织信息”中设置，留空时显示 RemoteCI。

::: tip 需要新版插件
应用守护由教室端插件部署并执行，需要升级到支持该功能的 RemoteCI 插件。“应用守护”页的设备列表会把旧版插件标为“插件版本过旧”。
:::

## 在哪里设置

| 位置 | 内容 |
| --- | --- |
| WebUI › 管理 › 应用守护 | 全局策略、单台设备的单独设置、更新 / 关闭 / 卸载守护、最近守护事件 |
| WebUI › 系统设置 › 常规 › 组织信息 | 恢复提示中的组织名 |
| REST | `GET/PUT /api/settings/app-guard`、`GET/PUT/DELETE /api/devices/{credentialId}/app-guard`、`GET /api/app-guard/events` |

“应用守护策略”系统权限控制全局与单设备策略；“设备应用守护”班级权限控制停用、卸载与立即更新守护。系统管理员始终拥有全部权限。

## 全局策略与单台设备

- **全局策略**：对所有教室电脑生效。保存后，在线设备立即收到；离线设备在下次连接服务端时收到。
- **单独设置**：在设备列表中点“单独设置”，这台设备就改用自己的完整策略；点“恢复沿用全局”即可撤销。
- **断网时**：插件会记住最近收到的策略，教室电脑断网启动时照样生效。

设备列表分别显示课表插件与独立守护的在线状态。课表离线而守护在线时，仍可通过设备行的“关闭守护”或“卸载守护”操作该设备；守护声明 `host.app-guard-manage` 能力后这些操作才可用。课表插件在线时，插件一分钟内会用插件包里的新版守护自动替换旧版本；也可以点“更新守护”立即强制覆盖升级，失败原因会显示在页面上。守护在线、能力完整且版本与课表插件一致即视为最新。

## 它是怎么工作的

ClassIsland 退出或被删除时，插件也随之停止，所以实际的守护工作由插件部署的独立小程序 `RemoteCI.Guard.exe` 完成：

- **位置与权限**：程序、配置和默认备份放在教室电脑的 `%LOCALAPPDATA%\RemoteCI\Guard`。普通守护随登录 Windows 自动运行，不需要管理员权限；增强模式的服务文件位于 `%ProgramData%\RemoteCI\Guard`。
- **不依赖 ClassIsland**：它使用 Windows 10/11 自带的 .NET Framework 4.8，ClassIsland 连同自带的运行时一起被删除后照样能工作。
- **如何区分退出方式**：插件会在 ClassIsland 正常退出前留下标记。有标记时按“退出自启”的延时处理；没有标记就视为意外退出。远程升级 ClassIsland 的 15 分钟内，守护不做干预。
- **开机启动**：守护登录后启动时，如果 1 分钟内 ClassIsland 没有自己启动，并且开启了“开机自动启动”，就由它启动；关闭该项后守护照常运行，只是不在开机时代为启动。
- **自我修复与自动更新**：ClassIsland 运行时，插件每分钟检查一次守护程序：被结束就重新拉起，被删除就重新部署，与插件自带的版本不一致就替换为新版本。维护过程不弹 UAC；增强服务的安装或路径变更在下次收到策略时处理。
- **守护云端通道**：插件把云端地址和由当前用户 DPAPI 加密的设备令牌写入 `connection.json`。守护以 `client=guard` 建立独立 WebSocket，只接收守护策略、远程打开以及关闭 / 卸载命令，不接收班级账号、课表或普通控制命令。

### 备份与恢复

- **备份范围**：ClassIsland 安装目录（含文件夹版的 `data`、插件与配置），以及安装目录之外的 ClassIsland 数据目录。日志、缓存和临时文件不备份。
- **何时备份**：仅在 ClassIsland 运行时按设定间隔（默认 24 小时）增量备份；ClassIsland 版本变化后立即备份一次。
- **自动跳过**：需要备份的内容超过 2 GB，或安装目录比上次备份少了 30% 以上的文件（疑似正在被删除）时，跳过本次备份并上报“备份失败”。
- **如何判断被删除**：启动器（文件夹版为安装目录下的 `ClassIsland.exe`）或安装目录缺失，10 秒后复查仍缺失。
- **恢复方式**：只补回缺失的文件，不覆盖仍存在的文件，也不删除多出来的文件。恢复后重新启动 ClassIsland，并在新打开的 ClassIsland 中弹出提示；恢复失败时 5 分钟后再试。

### 守护事件

“应用守护”页底部列出最近的守护事件，保留 90 天：

- 已自动恢复
- 恢复失败
- 意外退出后重启
- 退出后自启
- 频繁崩溃暂停重启
- 备份完成
- 备份失败
- 增强安装失败
- 远程启动

其中“已自动恢复”和“恢复失败”还会以个人通知的形式发给全部系统管理员（WebUI 铃铛、浏览器通知、手机、手表与 AstrBot）。

## 关闭与卸载

守护独立在线时，即使 ClassIsland 与插件离线，也可在“应用守护”页对单台设备执行：

- **关闭守护**：停用守护策略，结束守护进程并删除登录自启项，但保留守护程序和增强服务，之后重新启用策略即可恢复。该操作不需要 UAC。
- **卸载守护**：先请求 UAC 卸载增强服务与登录任务，再停用策略、结束守护进程并删除登录自启项；守护进程退出后延迟删除默认目录及所有额外备份目标。取消 UAC 或卸载失败时不清理本地文件。

两种操作成功后都会保存该设备的停用覆盖，避免下次连接时被原全局策略重新拉起。也可以在全局或单台设备表单中关闭总开关，由插件按完整策略执行原有清理流程。

## 注意事项

- 应用守护用来防止误操作和随手关闭、删除，不是防篡改机制。熟悉系统或有管理员权限的人仍然可以停止服务、修改任务或同时删除守护程序与备份。
- 通过 Microsoft Store（MSIX）安装的 ClassIsland 不支持“禁止删除”，其余功能照常生效，并会上报一次说明。
- 只守护当前登录 Windows 账号的 ClassIsland；多个 Windows 账号需要各自登录过一次 ClassIsland，插件才会为该账号部署守护。
- 额外备份路径所在磁盘不可用时会记录失败；至少一个目标成功即保留可恢复副本。
- 守护目录在 `%LOCALAPPDATA%` 中；如果整个用户配置文件被删除，备份也会一起丢失。
- 接口说明见 [API 接入 · 应用守护](../server/api.md#应用守护)。
